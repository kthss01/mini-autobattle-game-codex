# 작업 기록 및 티켓 3~7 준비 계획

이 문서는 **현재까지 구현된 범위(티켓 1~2)**를 먼저 정리하고, 이후 티켓 3~7을 순차적으로 진행하기 위한 준비 체크리스트를 제공합니다.

## 1) 현재까지 작업 내역(문서화 우선)

### 1-1. 이미 완료된 기반 작업
- 모노레포 구성 (`packages/sim`, `packages/client`)
- `sim` 데이터 스키마/타입/더미 데이터 구성
  - 챔피언/스킬/태그/시너지 데이터
- 개발/빌드/테스트 기본 파이프라인 구성
- 클라이언트 Phaser 부트스트랩 및 기본 씬 구성

### 1-2. 문서화 1차 작업(가장 먼저 수행)
1. `README.md`에 현재 범위를 “티켓 1~2 완료”로 명시
2. `packages/sim`의 공개 API(현재/예정)를 표로 정리
3. 티켓 3~7 목표/완료기준/테스트 기준을 문서화
4. 변경 이력(작업 로그) 섹션 생성

### 1-3. 문서화 산출물
- 본 문서: `docs/작업기록_및_티켓3-7_준비계획.md`
- 프로젝트 진입 문서: `README.md` (요약 + 링크)
- 협업 규칙 문서: `CONTRIBUTING.md` (언어/커밋/PR 규칙)

## 2) 티켓 3: sim 코어 구현(헤드리스)

### 목표
- `World / Unit / Combat / Effects / Match` 구현
- fixed-step 업데이트 루프 도입
- `runMatch` 구현
- 결정론(seed) 기반 smoke test 통과

### 구현 준비
- `packages/sim/src/sim/*.js`의 placeholder 제거 및 책임 분리
- tick 단위를 상수화 (예: `dt = 0.05`)
- RNG 사용 지점 단일화 (`rng.js`)로 재현성 확보

### 완료 기준(DoD)
- 같은 seed + 동일 입력에서 결과가 동일
- `runMatch` 반환값에 승패/라운드 시간/통계 기초값 포함
- smoke test에서 최소 1개 고정 시나리오 통과

---

## 3) 티켓 4: AI 구현

### 목표
- AI tick 0.25s + FSM
- 타겟 선정 + 규칙 기반 스킬 사용

### 구현 준비
- `AI.js`에 FSM 상태 정의 (`Idle`, `Acquire`, `Cast`, `Recover`)
- 0.25초 간격 AI 업데이트 스케줄러 설계
- 스킬 사용 규칙 우선순위(거리, 마나, 쿨다운, 체력조건) 명세

### 완료 기준(DoD)
- AI tick 주기 고정 동작
- 근접/원거리 유닛 각각 정상 타겟 선정
- 스킬 사용 규칙이 로그/통계로 검증 가능

---

## 4) 티켓 5: 메타(상성/시너지) 적용

### 목표
- `TAG_MODIFIERS` 적용(피해/힐 배율)
- `TEAM_SYNERGIES` 적용(팀 상시 버프)

### 구현 준비
- 계산 파이프라인: 기본값 → 태그 상성 → 시너지 → 최종 결과
- 버프 적용 시점(전투 시작 1회 vs 실시간 갱신) 명확화
- 중첩 규칙(가산/곱연산) 문서화

### 완료 기준(DoD)
- 상성/시너지 단위 테스트 통과
- 예상 배율과 실제 계산값이 일치
- `runMatch` 결과 통계에서 보정 영향 확인 가능

## 5) 티켓 6: Phaser 렌더링 연결

### 목표
- `MatchScene`에서 `createMatch()` 후 매 프레임 `step`
- 유닛 스프라이트/HP 바 표시
- 간단 이펙트(원형 AOE, 투사체)

### 구현 준비
- sim 엔티티 id와 렌더 오브젝트 매핑 테이블 도입
- 뷰 계층(`UnitView`, `ProjectileView`, `FxView`) 역할 분리
- 씬 업데이트 루프에서 sim tick과 렌더 보간 전략 결정

### 완료 기준(DoD)
- 전투 진행이 화면에서 연속적으로 관전 가능
- 체력 변화/사망/투사체 이동이 시각적으로 반영
- 성능 저하 없이 기본 전투 재생 가능

---

## 6) 티켓 7: 결과 화면/통계

### 목표
- `ResultScene`에 승패/점수/유닛별 딜/힐/킬/데스 출력
- seed 재시작 버튼 제공

### 구현 준비
- `Match` 결과 객체 스키마 확장 (팀/유닛 단위 통계)
- `ResultScene` 표시용 포맷터 유틸 설계
- 재시작 시 seed 재사용/재생성 모드 분리

### 완료 기준(DoD)
- 결과 화면에서 핵심 지표 한 번에 확인 가능
- 동일 seed 재시작 시 동일 결과 재현
- 다른 seed 실행 시 결과 변동 확인 가능

## 9) 추가 작업 기록 (후속 피드백 반영)

### 9-1. 안정성/정합성 보완
- `MatchScene`이 결과 화면에서 전달한 `seed`를 실제로 재사용하도록 수정했습니다.
  - 기존에는 `this.game.config.seed`를 읽어 재시작 seed가 고정될 수 있었고,
    이제 `init(data)`에서 전달 받은 seed를 전투 생성에 사용합니다.
- `Combat`의 `POINT` 타겟 스킬에 대해 **시전 거리(range) 검증**을 추가했습니다.
  - 사거리 밖 좌표를 지정한 경우 스킬이 무효 처리되어 룰 정합성이 개선됩니다.
- `World` 생성 시 팀 입력에 알 수 없는 champion id가 있으면 즉시 에러를 던지도록 검증을 추가했습니다.

### 9-2. AI 규칙 개선(일반화)
- 힐러의 단일 힐 선택을 `aiHint.useWhen === 'LOW_HP_ALLY'` 기반으로 우선 탐색하도록 보완했습니다.
- ON_COOLDOWN 계열 스킬은 하드코딩 id 외에도 `aiHint`를 보고 사용하도록 확장했습니다.
- 후열 유지 판단 로직을 헬퍼(`shouldKeepBackline`)로 추출해 가독성을 높였습니다.

### 9-3. 검증 메모
- 환경상 npm 레지스트리 접근 제한(403)으로 `npm install`/`vitest` 재설치가 불가능한 상황이라,
  이번 후속 수정은 `node` 스크립트를 통한 결정론/seed 전달/사거리 검증 중심으로 확인했습니다.
